# 图像质控与建案门控说明

AI 智能建案（`POST /training/ai-cases`）在调用 AI 分级前，会先对左右眼底图各做一次质控。质控不通过时不建案，返回 409，由前端弹窗让教师决定：重新上传、确认后继续，或人工放行。

## 1. 每眼的质控流程

1. **本地预检**（`app/services/image_precheck.py`）：不调用模型，命中下列任一条件就直接判为「不可判读」：
   - 文件无法解码；
   - 短边小于 `256` px；
   - 平均亮度低于 `12`（过暗）或高于 `243`（过曝）；
   - 像素标准差低于 `4`（几乎是纯色图）。
2. **质控模型**：预检通过后调用 CSU 质控接口，返回 `good / usable / poor / ungradable` 及置信度。
3. **降级**：模型调用失败，或返回的结果里没有可识别的等级时，该眼记为「未评估」（`unknown`）。未评估**不算合格**，但也不拦截建案。

每眼的结果都带 `source` 字段：`PRECHECK` 表示本地预检，`MODEL` 表示质控模型，`NONE` 表示未评估。

## 2. 门控规则（按顺序检查）

| 情况 | 409 `kind` | 怎样才能继续 |
| --- | --- | --- |
| 文件名里的眼别和上传位不一致（例如把 `OS` 文件传到右眼位） | `LATERALITY_CONFLICT` | 勾选 `confirm_laterality=true` |
| 任一眼不可判读 | `QUALITY_UNGRADABLE` | 填写 `override_reason`（必填，最多 255 字） |
| 任一眼质量差 | `QUALITY_POOR` | `confirm_low_quality=true`，或已经填写放行理由 |

409 响应的 `data` 包含 `kind`、`message`、`reasons`（每眼一行原因）、`quality`（每眼结果）和 `laterality`。如果一组图片同时命中多项，前端会逐项弹窗；已确认的项会在重新提交时保留，**换图或重置后清空**。

## 3. 留痕与影响范围

- 每眼的质控结果都会写入原图记录；人工放行的理由、操作人和时间写在病例上。
- 建案成功后，返回体里带 `quality`、`qualityWarnings`、`laterality`、`qualityOverride`，成功页会展示出来。
- **练习和考试抽题默认排除**含「差 / 不可判读」原图的病例。没有质控记录的历史病例不受影响。
- 金标准列表新增「图像质控」筛选（`qualityLevel=LOW / OK / UNKNOWN`）。
- 病例详情返回 `qualitySummary`（仅教师和管理员可见）。金标准弹窗顶部据此显示低质量横幅，并注明是否已人工放行。

## 4. 验收要点

1. 上传一张纯黑图：弹出「图像不可判读」，原因注明「本地预检」；不填理由时「人工放行」按钮不可点。填写理由后建案成功，成功页显示放行提示。
2. 上传模型判为「差」的图：弹出「图像质量较差」。点「已知晓，仍继续建案」后建案成功，病例被标记为低质量。
3. 把 `xxx_OS.jpg` 传到右眼位：弹出「请确认眼别」。点「眼别无误，继续」后进入后续检查。
4. 断开质控服务后建案：不拦截，成功页显示「未评估」。
5. 低质量病例不会出现在练习 / 考试抽题中。在金标准列表筛选「质量差 / 不可判读」能找到它，打开金标准弹窗可以看到横幅。
