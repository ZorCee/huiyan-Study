# 题库标准化调研

> 本文只给方案，不改数据模型。标注「待确认」的条目需要产品决定后再开发。

## 1. 现状与本次问题的根因

### 1.1 题目和病例怎么关联

| 字段 | 位置 | 含义 |
| --- | --- | --- |
| `case_id` | `biz_question` | 关联 `biz_training_case.id`，为空即「通用题」 |
| `image_id` / `image_url` | `biz_question` | 题目引用的单张影像，可空 |
| `roi_box` | `biz_question` | 题目关注的区域 |
| `tags` | `biz_question` | JSON 数组，自由填写 |
| `difficulty` | `biz_question` | 难度 |

此外还有 `text_quiz.py` 里写死的 **14 道常规题**，它们不在数据库里，题号是 `c-cd`、`b-ex` 这类字符串。

### 1.2 为什么「选了病例却看不到题」

1. `ExamService.start()` 调用 `_ensure_text_paper(record)` 时没有传入 `db`，函数里 `if db is not None` 永远不成立，于是每道题都只从 14 道常规题里随机抽，和所选病例无关。**本次已修复。**
2. `get_questions_for_case()` 用通用题补齐时没有按病种筛选：算出了病种却没有用，直接按 id 取。**本次已改为同病种优先。**
3. 常规题补齐时 `build_paper()` 至少返回 3 道，导致每题总数可能超过 4。**本次已改为只取需要的数量。**
4. 文字题在学员进入考试时才确定，发布时老师看不到会出哪些题。**本次新增了 `POST /exam/preview` 和弹窗内预览。**

修复后，病例专属题仍然很少的话，大部分题会是补充的通用题。这是数据问题，不是代码问题，需要按下面的方案建设题库。

## 2. 一图多题、一题多图

**现在的限制**：一道题只能挂一个病例（`case_id`）和一张图（`image_id`），无法表达「对比左右眼」「同一患者随访前后对比」这类题。

**建议**：新增关联表 `biz_question_image`，保留现有字段以兼容。

```text
biz_question_image
  id            PK
  question_id   FK -> biz_question.id  (ON DELETE CASCADE)
  case_id       FK -> biz_training_case.id，可空
  image_id      影像 id，可空
  role          PRIMARY / COMPARE / REFERENCE   图在题中的作用
  roi_box       JSON，可空，按图记录关注区域
  sort_order    INT
  UNIQUE (question_id, image_id)
```

- 一图多题：同一 `image_id` 出现在多行。
- 一题多图：同一 `question_id` 出现在多行，用 `role` 和 `sort_order` 决定显示方式。
- 兼容：迁移时把每道题现有的 `case_id + image_id + roi_box` 写成一行 `role=PRIMARY`。旧字段保留为「主图」的冗余，读取逻辑优先查关联表，查不到再回退到旧字段。

**待确认**：一题最多几张图？对比题是否需要专门的作答界面（并排或切换）？

## 3. 逐图题和通用题怎么共存

| 类型 | 判定 | 用途 |
| --- | --- | --- |
| 逐图题 | 关联表里至少有一张图 | 必须看图作答，考读片能力 |
| 病例题 | 关联了病例但没有具体图 | 考这个病例的诊断、处理 |
| 通用题 | 什么都不关联 | 考指南、概念，可以补到任何病例 |

建议新增字段 `scope`（`IMAGE / CASE / GENERAL`），由保存时自动计算，不让老师手填，避免和关联关系不一致。

组卷时的优先级（和本次实现一致）：病例专属题 → 同病种通用题 → 其他通用题 → 常规题随机补齐。

**待确认**：通用题是否允许补到「看图」类病例？现在的做法是允许，但可能出现「病例是 AMD，题目考 DR 分期」的情况，因此本次按病种优先排序。

## 4. 标签体系

现在 `tags` 是自由填写，同一个病种可能出现 `DR`、`dr`、`糖网`、`糖尿病视网膜病变` 等多种写法，只能靠模糊匹配。

建议改为字典 + 多对多关联：

```text
biz_tag_dict      id, dimension, code, label, parent_id, sort_order, is_active
biz_question_tag  question_id, tag_id
```

| 维度 `dimension` | 示例取值 | 说明 |
| --- | --- | --- |
| `CATEGORY` 病种 | DR / AMD / 青光眼 / RVO | 和病例的 `category` 用同一套代码 |
| `DR_GRADE` DR 分级 | 0–4、DME | 只在病种为 DR 时可选 |
| `POINT` 考点 | 微血管瘤识别、IRMA、新生血管、黄斑水肿判断 | 两级：大类 → 具体考点 |
| `DIFFICULTY` 难度 | 入门 / 初级 / 中级 / 高级 | 替代现在单独的 `difficulty`，旧字段保留 |
| `SOURCE` 出处 | 国际分级标准、国内指南 | 和 `source_guideline` 对应 |

- 录题界面改为按维度的下拉多选，不再允许自由输入。
- 旧的 `tags` 迁移：按别名表映射到字典（例如 `dr`、`糖网` → `CATEGORY:DR`），映射不上的放进「待整理」，由老师人工确认。

**待确认**：考点清单由谁维护、以哪份指南为准？是否允许老师新增考点，还是只能管理员维护？

## 5. 组卷规则

### 5.1 目标

1. **题量**：每个病例固定 4 道文字题（现状），整卷题量 = 病例数 × 4。
2. **覆盖**：整卷的考点尽量不重复，指定的考点至少出现一次。
3. **难度分布**：可以按比例设置，例如入门 20%、初级 40%、中级 30%、高级 10%。
4. **可预览、可复现**：老师发布前看到的就是学员拿到的。

### 5.2 建议的规则

- 发布时可选「题目固定」：在发布时把每个病例的题号存到 `biz_exam_paper.question_plan`（JSON），学员进入时直接使用，所有人题目相同。默认仍是现在的「进入时确定」。
- 抽题时按「专属题 → 同病种同考点通用题 → 同病种通用题 → 其他」的顺序取，同一张试卷内不重复使用同一道通用题。
- 难度比例无法满足时，在预览里明确提示差多少道，不悄悄降级。
- 常规题随机补齐是过渡方案，题库建好后建议关闭，题量不够就拒绝发布并提示。

**待确认**：是否要求所有学员题目完全一致（关系到「题目固定」是否作为默认）？难度比例是全校统一还是每场考试单独设置？

## 6. 历史数据迁移

| 步骤 | 内容 | 是否可回退 |
| --- | --- | --- |
| 1 | 新建 `biz_question_image`、`biz_tag_dict`、`biz_question_tag`，不删任何旧字段 | 可以，删表即可 |
| 2 | 把每道题的 `case_id/image_id/roi_box` 写入关联表 | 可以，旧字段未动 |
| 3 | 导入标签字典和别名表，迁移 `tags`，生成「待整理」清单 | 可以 |
| 4 | 读取逻辑切到新表，旧字段只做回退 | 改配置即可切回 |
| 5 | 观察一个学期后，再决定是否删除旧字段 | — |

已经开始或已结束的考试使用的是存在 `text_question_ids` 里的题号，迁移不影响它们的回看和成绩。

## 8. 需要产品确认的决策点汇总

1. 一题最多关联几张图；对比题是否要专门的作答界面。（第 2 节）
2. 通用题能否补到不同病种的病例。（第 3 节）
3. 考点清单的来源和维护权限。（第 4 节）
4. 默认是否「发布时固定题目」，让所有学员题目一致。（第 5 节）
5. 难度比例的设置粒度。（第 5 节）
6. 常规题随机补齐何时关闭。（第 5 节）
7. 老师是否只能给自己任教的组发考试（需要新增老师与带教组的绑定，本期未做）。
